# Limitations and Future Scope

## Synthetic-data limitations

The supplied 1,000-row dataset is generated by
`datasets/generate_synthetic_data.py`; it contains no real student information.
Its label is defined directly from the three input features:

```text
score = 0.40 * previous_marks
      + 0.30 * attendance
      + 0.30 * min(study_hours * 10, 100)
      + Normal(0, 8)
pass if score >= 50; otherwise fail
```

Consequently, evaluation measures whether models recover this artificial rule
under one generated sample. It does not show how students perform in actual
courses, exams, or institutions. Synthetic noise and feature ranges are also
chosen by the generator and may not represent educational data distributions.

The expected composite score under the generator's feature ranges is above the
50-point threshold, and the realized dataset has 733 pass (73.3%) and 267 fail
(26.7%) records. The majority class is therefore built into this particular
sample.

## Class imbalance and observed errors

The stratified test split has 110 pass and 40 fail records. The original ANN,
tested at threshold 0.5, predicted every record as pass. It achieved accuracy
0.733333, equal to the pass proportion, but fail recall was 0 and all 40 fails
were missed.

Logistic Regression used its validation-selected threshold
0.45458775758743286. It correctly identified 28 of 40 fails and 102 of 110
passes. It missed 12 fails and incorrectly classified 8 passes as fail. Its
test fail recall was 0.700000, pass recall 0.927273, and balanced accuracy
0.813636. These counts show that the threshold changes the error balance; they
do not establish an acceptable risk level for actual educational use.

Accuracy alone is insufficient when a majority class is present. A
majority-only prediction can attain 73.33% accuracy on this test split while
having no fail detection. Future reports should continue to include
class-specific precision and recall, F1, balanced accuracy, confusion matrices,
and ROC-AUC. The relevant error costs should be defined before choosing a
threshold for any real application.

## Split and evaluation limits

- The experiment uses one fixed 70/15/15 stratified split: 700 training, 150
  validation, and 150 test rows.
- Only 40 fail cases are in the test partition; a few changed predictions can
  noticeably affect fail-specific metrics.
- Per-model thresholds were selected using the validation predictions. The
  resulting validation metrics are therefore selection results, not an
  independent final estimate.
- The test split was held out for inference and reporting, but it is still a
  synthetic sample created from the same generator as training data.
- No external institution, time period, subgroup, or real cohort has been used
  to validate generalization.
- The app's class probabilities are not demonstrated to be calibrated.

## Input and feature limitations

Only study hours, attendance, and previous marks are used. Definitions and
recording practices for these fields can differ between students or
institutions. Important contextual factors are absent. App input ranges follow
the synthetic generation ranges; records outside them are not accepted, and
performance within the synthetic ranges still does not imply real-world
validity.

## Future scope

1. Obtain an appropriately authorized, privacy-protected educational dataset
   with documented outcome definitions and representative cohorts.
2. Keep a genuinely untouched external or later-time test set and use
   cross-validation within training data for model development.
3. Assess class-specific errors by relevant groups where legally and ethically
   appropriate, and document data governance and intended use.
4. Establish probability calibration and threshold criteria from explicit
   operational costs rather than selecting a threshold solely by a metric.
5. Compare class weighting, resampling, calibration, and additional models
   using identical splits and predeclared metrics.
6. Add drift checks, model/version metadata, input auditability, and monitoring
   before any real deployment.
7. Add a consolidated experiment orchestration command only if the workflow
   later needs one; the current `main.py` intentionally handles data inspection
   and preprocessing only.

Until such work is completed, the project and Streamlit app should remain an
educational demonstration based on synthetic data, not a student assessment
system.
