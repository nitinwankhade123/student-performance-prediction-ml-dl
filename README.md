# Student Performance Prediction Using Machine Learning and Deep Learning

An undergraduate demonstration project that compares an Artificial Neural
Network (ANN), Logistic Regression, and Random Forest for binary student-result
classification. The project includes a reproducible synthetic dataset, a
training-fitted preprocessing scaler, validation-based model/threshold
comparison, an independent test run, and a local Streamlit interface.

> **Synthetic-data notice:** All records and labels in the supplied dataset are
> generated by code. They are not real student records and do not establish
> real-world prediction performance. Do not use this app for academic decisions.

## Problem statement

Given study hours per day, attendance percentage, and previous examination
marks, classify a record as `fail` or `pass`. In this project, the label is
synthetically generated from a weighted score rather than taken from observed
examination outcomes.

## Objectives

- Demonstrate a complete tabular binary-classification workflow.
- Generate and inspect clearly labelled synthetic educational data.
- Split data with stratification and fit feature scaling on training data only.
- Implement and train a small PyTorch ANN.
- Compare the ANN with Logistic Regression and Random Forest on one fixed
  validation split.
- Select thresholds using validation data, then report one independent test
  evaluation without test-based tuning.
- Serve the saved Logistic Regression model in a local Streamlit app.

## Features and target

| Field | Meaning | Synthetic generation range |
|---|---|---:|
| `study_hours` | Study hours per day | 0–10 |
| `attendance` | Attendance percentage | 40–100 |
| `previous_marks` | Previous exam marks | 20–100 |
| `result` | Target label | `fail` or `pass` |

Preprocessing encodes `fail = 0` and `pass = 1`. The Streamlit interface uses
the same feature order and restricts inputs to the ranges above.

## Central data-preparation commands

From the project root, the central entry point offers explicit data commands:

```shell
python main.py inspect
python main.py prepare
```

`inspect` loads and reports the source CSV without writing files. `prepare`
loads and validates it first, then runs the existing preprocessing module and
writes the scaler and processed splits. Neither command trains a model or
starts Streamlit. Launch the app separately using the instructions below.

## Methodology

1. Generate 1,000 seeded synthetic records and inspect the CSV.
2. Encode labels, stratify into 70% training, 15% validation, and 15% testing.
3. Fit `StandardScaler` on the 700 training records only, then transform all
   three splits with the saved scaler.
4. Train the ANN on training data and monitor validation loss. Do not use the
   test split for training or model selection.
5. Fit Logistic Regression and Random Forest using the same processed training
   split. Train a second ANN with a training-only weight for the minority fail
   class.
6. Compare all four models and select each comparison threshold on validation
   predictions by maximum balanced accuracy. Ties are resolved by higher
   fail-class precision, then by closeness to 0.5.
7. Independently evaluate the Logistic Regression candidate on the test split
   with its frozen validation threshold.

Detailed procedures are in [docs/methodology.md](docs/methodology.md).

## Models and algorithms

### ANN

The PyTorch model is `Linear(3, 8) → ReLU → Linear(8, 1)`. It has **41 trainable
parameters** and returns a raw logit. Training uses `BCEWithLogitsLoss`, Adam
with learning rate 0.001, full-batch updates, up to 100 epochs, and validation
loss early stopping with patience 10. In the recorded run, all 100 epochs were
completed; early stopping did not trigger. The minimum validation loss was
0.570101 at epoch 100.

### Classical baselines

- Logistic Regression: `C=1.0`, `lbfgs`, `max_iter=2000`, no class weighting.
- Random Forest: 300 trees, no maximum depth, minimum split 2, minimum leaf 1,
  no class weighting.
- Class-weighted ANN: same architecture and 100-epoch full-batch Adam setup as
  the baseline ANN; fail-class loss weight 2.743316 and pass weight 1.0.

## Independent test results

The test split contains 150 records: 40 fail and 110 pass. Logistic Regression
used the frozen validation-selected threshold
`0.45458775758743286`. The original ANN test results used threshold `0.5`.

| Model | Threshold | Accuracy | Fail recall | Pass recall | Balanced accuracy | ROC-AUC |
|---|---:|---:|---:|---:|---:|---:|
| Original ANN | 0.5 | 0.733333 | 0.000000 | 1.000000 | 0.500000* | 0.699773 |
| Logistic Regression | 0.45458775758743286 | 0.866667 | 0.700000 | 0.927273 | 0.813636 | 0.904545 |

`*` ANN balanced accuracy is derived from its saved confusion counts; it is not
a column in `results/test_metrics.csv`.

With `pass = 1` as the positive class, the Logistic Regression test confusion
matrix is **TP=102, TN=28, FP=12, FN=8**. In matrix form (actual rows and
predicted columns ordered `[fail, pass]`):

```text
[[28, 12],
 [ 8,102]]
```

The ANN predicted every test record as pass: 40 fails were missed. Its 73.33%
accuracy equals the pass share in the test split. This is why accuracy alone is
not sufficient; class recall, balanced accuracy, and the confusion matrix
expose fail-detection behavior.

ROC-AUC measures ranking across thresholds, not classification quality at the
chosen threshold. Logistic Regression's test ROC-AUC was 0.904545; this is an
observed result on the synthetic test split, not a real-world performance
claim. Saved figures are in `results/final_test_confusion_matrix.png` and
`results/final_test_roc_curve.png`.

## Run the Streamlit app locally

From the project root, install the pinned dependencies and launch the app:

```shell
python -m pip install -r requirements.txt
python -m streamlit run deployment/app.py
```

On Windows, if `python` is not on `PATH`, replace `python` in these commands
with the full path to the configured Python executable.

The app loads `experiments/logistic_regression/model.joblib` and the existing
training-fitted `artifacts/standard_scaler.joblib`. It uses the frozen threshold
above and performs inference only; it does not train when launched. It has been
verified locally with input (6 study hours, 80 attendance, 70 previous marks),
which produced Pass 98.7% and Fail 1.3% for that sample.

## Limitations and future scope

- Synthetic labels are generated from a known rule and are not actual academic
  outcomes.
- Pass is the majority class (733 of 1,000 records); the original ANN's test
  accuracy matched the majority-class rate while detecting no fails.
- The dataset has 1,000 rows and one fixed stratified split; small-sample and
  split variation may affect metrics.
- The Logistic Regression threshold was selected on validation data, so its
  validation metrics are selection results. The test set was reserved for
  independent evaluation.
- Three features omit context, and the displayed probabilities are not
  demonstrated to be calibrated for real-world use.

Future work could validate on authorized real educational data, repeat
evaluation across multiple splits or cross-validation folds, document privacy
and fairness safeguards, calibrate probabilities, and compare threshold choices
against clearly stated educational costs. See
[docs/limitations_and_future_scope.md](docs/limitations_and_future_scope.md).
